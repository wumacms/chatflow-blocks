  只能走 granular token with bypass 2FA
- 恢复码用于找回登录，不要指望它填 `--otp`

## 多风格区块（variant × tone）设计方案 + Hero 实现步骤

需求：每个区块组件支持多种风格，数据结构不变，靠参数切换。产出 `PLAN-Hero多风格实现步骤.md`（根目录，
与既有 `AUDIT-*.md` 同级；不进 docs/guide 是为了不动 VitePress 侧边栏）。

**核心架构决策（后续所有组件照此执行，勿回退）**
- 三个维度必须分开：`variant` = DOM 结构差异（独立子组件）；`tone` = 皮肤，只改 CSS 变量；暗色模式沿用 `.dark`
- **正交组合**：结构变体 × 皮肤色调，组合数是乘法、代码量是加法
- 三层：数据契约层（`XxxData` + variant/tone 字面量联合）→ Token 层（`--cf-{组件}-*` 语义变量）→ 变体渲染层（registry 分派）
- **零 v-if 原则**：能靠变量归零（border-width:0 / bg:transparent）表达的绝不用分支；图片装饰框常驻容器即为此例
- 数据结构三条铁律：① variant/tone 必须是字面量联合 + 有默认值 + 非法值静默回退；② 视觉参数绝不进数据契约
  （禁 `bgColor`/`rounded` 之类，否则 AI 生成的 JSON 会失控）；③ 变体专属字段保留顶层并文档标注
- 每个组件变体控制在 3-5 个，超过说明把 tone 误判成了 variant

**以两个 Hero 样本验证的结论**
两个样本（classic 白底渐变 / brutal 新粗野主义）DOM 骨架**完全一致**，差异 100% 是颜色/字重/边框量/阴影/圆角/装饰
→ 它们是**同一个 variant（centered）+ 两个 tone**，不是两个 variant。`HeroCentered.vue` 可做到 0 个 v-if。
标题高亮用语义化 `<mark>`（title 已支持 v-html，零解析零转义），不用新增 `highlight?: string[]` 字段。

**Tailwind 4 消费变量写法（写死，勿改）**
- 颜色 `bg-[var(--x)]` / `text-[color:var(--x)]` / `border-[color:var(--x)]`
- 阴影 `shadow-[var(--x)]`、圆角 `rounded-[var(--x)]`、边框宽 `border-[length:var(--x)]`、渐变 `bg-[image:var(--x)]`
- 字重/行高/旋转/高度 → 不进 Tailwind，写在 tone 的原生 CSS 规则里
- 理由：Tailwind 按需扫描静态类名，`bg-${tone}-600` 拼接会被 purge；`normalize.ts` 的 `badgeColor()` 用 map 返回完整类名是同样道理
- 按钮要显式 `border-solid`（Tailwind 4 宽度工具类依赖 `--tw-border-style`）；brutal 的 hover 阴影位移要求按钮用 `transition` 而非 `transition-colors`

**发现的既有真实缺陷（本次方案中修复）**
1. `theme.css` 定义 `--cf-primary` 等变量但组件从未消费（Hero.vue 全硬编码 `bg-indigo-600`），
   `docs/guide/theming.md` 承诺的「覆盖变量即生效」实际是假的 → classic tone 改用 `var(--cf-primary)`
2. `Hero.vue` 自己写 `computed` 而没用 `useMergedData` → 统一收口到 `useHeroData`
3. `py-16 md:py-24` 应为 `pt-16 pb-20`（与两个样本一致）；`bg-gradient-to-b` 在 Tailwind 4.3 已废弃，改 `bg-linear-to-b`

**兼容迁移**：旧 `variant: 'default'` 归一为 `'centered'`；`'background'` 保持；未传 `tone` 默认 `'classic'`。
旧 JSON 渲染结果必须与改动前一致。

## 追加第三个 Hero 样本：split 变体 + amber 皮肤

用户给的第三个样本是**左右分栏**（`grid md:grid-cols-2`），DOM 与 centered 不同，
所以是「新 variant + 新 tone」各加一个，正好验证正交设计。

**职责划分（写成硬规则记入 tones.md，勿回退）**
| 归 variant（骨架与尺度） | 归 tone（色彩与质感） |
| --- | --- |
| 栅格/布局、区块内边距 | 颜色、字重、行高 |
| 标题字号（响应式 md: 断点） | 按钮字号/内边距/圆角 |
| 描述最大宽度、图片容器尺寸约束 | 描边宽度与颜色、阴影形态、`<mark>` 外观 |

标题字号**不进 tone**：响应式值放变量会让每个 tone 都写一遍媒体查询，得不偿失。

**改动**
- 新增 `Hero/HeroActions.vue`（按钮组，被所有变体共用，变体只透传容器 class）
  — centered 与 split 的按钮标记完全一致，抽出来避免复制两份
- 新增 `variants/HeroSplit.vue`（两列栅格 + `py-20 md:py-28` + `text-5xl md:text-6xl` + `max-w-lg` 描述）
- `registry.ts` 的 `split` 从「回退 centered」改为指向 `HeroSplit`
- `tones/hero.css` 加 amber 块（锌灰渐变 + 琥珀强调）；**新增 3 个变量**：
  `--cf-hero-btn-size`、`--cf-hero-btn-{primary,secondary}-text-hover`（后两个是为匹配样本的
  hover 换文字色），三套 tone 都要补齐
- `types.ts` HeroTone 加 `'amber'`；`normalizeTone` 加分支

**踩坑**
- 「无阴影」不要用 `none` 写进 `--cf-hero-*-shadow`：Tailwind 会把 `--tw-shadow` 拼进
  `box-shadow: var(--tw-inset-shadow),...,var(--tw-shadow)` 的多层列表，`none` 混进去整条声明失效。
  用 `0 0 #0000` 代替
- `<mark>` 在 amber 下是「只改文字色、不铺底色」（`mark-bg: transparent` + `mark-c: #eab308`），
  与 brutal 的「色块 + 旋转」是同一组变量的不同取值——这正是正交设计的收益
